# Changelog

## Unreleased

- `scripts/install-skills.sh` installs the four skills for Codex, Cursor, GitHub Copilot, Gemini CLI, Antigravity, Devin Desktop, OpenCode, Cline and Claude Code without the plugin, for one user (`--user`) or one repository (`--project`). It links to the clone by default (`--copy` for copies), installs a shared skill folder once, never replaces a folder or link that it did not install (it then stops with exit code 1), and tells you how to install the `lore` command with the Word and PDF extras when it is missing. The agents and folders match qestack's installer.

- The `lore-resolve` skill: settle a vague value from the other sources, then the production code, then a person, in the order of `[ambiguity] order` in `lore.toml` (default `sources`, `code`, `ask`; a bad value is refused). The graphify code-graph tool is optional and needs the user's approval.
- The `lore-review` skill: guides a person through a Proposal pull request. It never sets `verified`; the reviewer adds that mark by hand.
- `lore convert` reads code files (Python, JavaScript, Java and others) only under a `[[sources]]` path with `basis = "actual"`, with no Markdown sections; a Source from code is titled with its lines (a quote before the first heading of a Markdown file now also gets its line). Hidden, dependency and build folders, files named like secrets (`.env`, `*secret*`, `*.pem`), code over 200 KB and files that are not UTF-8 are skipped, each with a reason.
- `lore propose`: applies a Proposal file. Each Source from a document is a verbatim quote; `lore propose` finds it in the converted text and records its exact span with the file's sha256 (ADR 0003). The pages are written, built and checked, then committed on a new branch; a failed check leaves the Knowledge Base as it was. A page given with only cites (each with `after`, the page text it supports) gets the new Sources and keeps its body and review; a page given with a body replaces the page and removes its review (a `verified` key in a Proposal is ignored). Any other page without a body is refused.
- The `lore-extract` skill: turn documents into a Proposal. The demo has an example Proposal from the Word BRD and the PDF rules.
- An agent extraction test (`evals/extract.py`): sets up a copy of the demo without its threshold Spec Conflict, runs agent sessions (1 by default, `--runs N`; `--model` picks the agent, the cost cap is pinned) and scores eight checks for each, such as "the Spec Conflict is found" and "every quoted span is right". The scoring has its own tests. Results and the rule for when to run it are in `evals/README.md`.
- `lore convert`: source documents listed under `[[sources]]` in `lore.toml` become cached text with character offsets, sections and a sha256 in `.lore/cache/`; unchanged files are not rewritten. Markdown and text need nothing extra; Word needs `domainlore[docx]` (mammoth + markdownify), PDF needs `domainlore[pdf]` (pypdf, with a page for each span). A document is converted again when its file, basis or converter changes.
- The demo policy document has a vague value ("how long a buyer counts as new is to be confirmed") that an agent must record as an Open Question, not guess; the example Proposal does so.
- The demo has a Word BRD (5 000 EUR) and a PDF export of the Confluence approval rules (10 000 EUR), generated by `scripts/gen-demo-docs.py`.
- `lore check` warns `unrecorded-gap` for an intended-only relation or transition on a page with `basis: actual` that no Gap page records. The exit code is unchanged, but `lore check --strict` now fails on it. To fix it, add a Gap page whose `about` lists the page and the relation target.
- CI gates retrieval hit@1 (70%) as well as hit@5 (96%).
- A held-out retrieval question set (12 questions) to judge `lore query` ranking changes. CI prints its result without a gate.
- Clearer Buyer and Four-eyes descriptions; a retrieval and agent-eval question for the inbox-link Gap.

## v0.1.0 (2026-10-30)

- OKF v0.2 Knowledge Base with seven domain types, typed relations, basis and trust tiers.
- LinkML schema with generated JSON Schemas for frontmatter validation.
- `lore init`, `build`, `check`, `query`, `explain`, `path`.
- Generated indexes, Area maps, context map, glossary, Relations blocks, and Mermaid lifecycle, journey, ER and navigation diagrams.
- `AGENTS.md` and `CLAUDE.md` pointer block, Cursor rule, `lore-use` skill, Claude Code plugin.
- Demo product `examples/order-approval` with two planted Gaps and a Spec Conflict; retrieval eval.
- Journey steps: `goto: []` ends the journey at that step, so a branch end no longer leads to the next step.
